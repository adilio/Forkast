## Design Specificity Verdict

Forkast feels purpose-built: cool paper, ruled work rows, restrained green, a persistent store rail, operational copy, and the recipe-to-store mechanism form a coherent working-kitchen language. Specificity weakens inside the long generic CRUD form and indistinct shopping loading state.

The deterministic scan returned `[]` with zero findings across `src`. Browser evidence nevertheless found a mobile sticky action bar obscuring about 42px of the Directions field and active navigation without `aria-current`. Mutable overlay injection was unavailable, so screenshots, DOM snapshots, and geometry measurements were the visual fallback.

## Overall Impression

The authored foundation and core routing mechanism are strong. The largest opportunity is to make data safety and interruption recovery as trustworthy as the visual world.

## What's Working

1. Desktop work rail and mobile labeled bottom rail fit the real contexts.
2. Serving adjustment, ingredient selection, store routing, and named completion feedback clearly express the core mechanism.
3. Import copy is honest about extraction limits and preserves an editable fallback.

## Priority Issues

1. **[P1] “Synced” overpromises data safety.** `navigator.onLine` does not prove Firestore acknowledged pending writes, and store loading can resemble an empty list. Fix with honest online/offline/loading/saving states and guarded submissions. Suggested command: `$impeccable harden`.
2. **[P1] Mobile navigation can silently destroy recipe work.** The long editor uses transient state while global navigation remains active. Persist a local draft, warn before unloading, and focus editor navigation. Suggested command: `$impeccable harden`.
3. **[P1] Recipe editor is an unstructured wall of fields.** Put title, servings, ingredients, and directions first; disclose description/source/image/notes under More details. Suggested command: `$impeccable distill`.
4. **[P2] Grocery destruction lacks recovery.** Confirm clearing completed items and provide recoverable feedback for row removal. Suggested command: `$impeccable harden`.
5. **[P2] Empty Recipes repeats its primary action.** Hide redundant header/tool actions until content exists. Suggested command: `$impeccable clarify`.

## Persona Red Flags

- **Alex (power user):** Multi-item routing has no progress/duplicate-click protection; the all-fields editor slows repeated entry.
- **Sam (accessibility-dependent):** Store controls use tab roles without tabpanel/arrow behavior, current navigation is not announced, and connectivity changes are not a live status.
- **Casey (distracted mobile):** Six persistent editor actions, a 1,716px form, and unprotected navigation make interruption costly; premature “Synced” undermines trust in the aisle.

## Minor Observations

- Search lacks a result count and one-tap clear affordance.
- Raw Firebase/Firestore messages may reach users.
- Static spotty-service reassurance may be mistaken for current status.
- “Nothing left” and “not loaded” need distinct shopping states.
- Invalid import URL recovery relies mainly on native validation.

## Questions to Consider

- Should trusted status communicate internet reachability or confirmed household data safety?
- Could the editor behave like a prep ticket: essentials first and optional annotations folded away?
- Should leaving an unfinished recipe require an explicit save-draft or discard choice?
